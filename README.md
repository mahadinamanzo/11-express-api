# Express Products API

A file-backed REST API built with Node.js and Express 5. Start the development
server with `npm run dev`; it listens on port `3000` by default, or on the port
specified by `PORT`.

Successful responses use `{ "data": ... }`. Errors use
`{ "error": { "message": "..." } }`; validation errors also include
`"fields": { "field": "reason" }`. In non-production environments, unexpected
server errors may include a stack trace. Production responses do not expose
stack traces.

## Endpoints

| Method | Path | Body | Success code | Error codes |
| --- | --- | --- | --- | --- |
| GET | `/api/health` | — | 200 | 500 |
| GET | `/api/products` | — | 200 | 500 |
| GET | `/api/products/:id` | — | 200 | 404, 500 |
| POST | `/api/products` | `name`, `sku`, `category`, `price`, `stock` | 201 | 400, 422, 500 |
| PUT | `/api/products/:id` | All editable fields: `name`, `sku`, `category`, `price`, `stock` | 200 | 400, 404, 422, 500 |
| PATCH | `/api/products/:id` | One or more editable fields | 200 | 400, 404, 422, 500 |
| DELETE | `/api/products/:id` | — | 204 | 404, 500 |

`POST` returns the created product and sets a `Location` header. Product IDs
and `createdAt` are generated by the server and are not writable fields.
`PUT` replaces all editable fields while preserving the ID and creation date;
`PATCH` changes only the supplied fields.

The list endpoint supports these optional query parameters:

| Parameter | Example | Behavior |
| --- | --- | --- |
| `category` | `?category=Audio` | Filters by category (case-insensitive). |
| `q` | `?q=wireless` | Case-insensitive search across name, SKU, and category. |
| `sort` | `?sort=price` or `?sort=-price` | Sorts by price ascending or descending. |

Valid categories are `Accessories`, `Audio`, `Displays`, `Power`, and `Video`.
SKUs must match `^[A-Z]{3}-\d{4}$` and be unique. Invalid product input
returns 422 with per-field messages. Malformed JSON returns 400.

## HTTP status codes

- **200 OK** — A read or update succeeded.
- **201 Created** — A product was created; the response includes its URL in
  `Location`.
- **204 No Content** — A product was deleted; the response has no body.
- **400 Bad Request** — The request could not be parsed, such as malformed
  JSON.
- **404 Not Found** — The product or route does not exist.
- **422 Unprocessable Content** — The JSON was parsed, but product validation
  failed.
- **500 Internal Server Error** — An unexpected server-side failure occurred.

## Example curl commands

Examples below use a POSIX-style shell. Replace `PRODUCT_ID` with the ID
returned by the create request.

```sh
# Health check
curl -i http://localhost:3000/api/health

# Search and sort
curl -i "http://localhost:3000/api/products?q=wireless&sort=price"

# Create a product (inspect the response body and Location header)
curl -i -X POST http://localhost:3000/api/products \
  -H "Content-Type: application/json" \
  -d '{"name":"USB-C Hub","sku":"HUB-1234","category":"Accessories","price":34.99,"stock":15}'

# Replace all editable fields
curl -i -X PUT http://localhost:3000/api/products/PRODUCT_ID \
  -H "Content-Type: application/json" \
  -d '{"name":"USB-C Hub Plus","sku":"HUB-1234","category":"Accessories","price":44.99,"stock":10}'

# Change only the stock
curl -i -X PATCH http://localhost:3000/api/products/PRODUCT_ID \
  -H "Content-Type: application/json" \
  -d '{"stock":8}'

# Delete a product
curl -i -X DELETE http://localhost:3000/api/products/PRODUCT_ID
```

For a complete interactive request sequence—including validation failures,
duplicate SKU, sorting, lookup, and 404 examples—open [requests.http](./requests.http)
with the VS Code REST Client extension.
